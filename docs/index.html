The Blender Game Engine,
rebuilt for what comes next.

BGE Revived is a from-scratch game engine inspired by the workflow of Blender 2.49b: author in Blender, press play, and the engine runs your world. This time the runtime is standalone, data-oriented, fixed-step, modern-rendered, and built to last.

Same workflow. None of the same walls.

The original BGE was ahead of its time, but it carried the constraints of 2001: a single-threaded runtime, a fixed-function renderer, frame-rate-coupled logic, and an editor bolted into Blender. We keep the good part — the direct connection between authoring and playing — and replace everything underneath.

⚡

Fixed-step simulation

Gameplay, physics and scripts always see a constant 120 Hz delta. Rendering runs independently and interpolates, so a slow frame never changes how the game behaves.

🧱

Data-oriented core

Sparse-set ECS, generational entity handles, and a fork-join job system. Transform updates, culling, and animation can scale across cores instead of serialising through one scene graph.

🌅

Modern renderer

HDR forward shading, metallic/roughness PBR, directional shadows, instanced draw batching, frustum culling, ACES tone mapping and FXAA — with a Vulkan RHI planned.

🐍

Python that fits

Current CPython embedded in the runtime, with a narrow, versioned bge API. Native components do the hot work; Python handles gameplay and glue.

🎛️

Blender stays the editor

No second editor to maintain. A Blender addon will sync scenes and assets to the runtime and provide the 2.49b-style “press Play” loop over a live link. The file-based bridge already ships: export a .blend and render it headlessly.

📦

Cooked, not coupled

glTF and image sources are imported, validated, and cooked into packs. A shipped game never needs Blender, Python source, or a .blend file to run.

Build it today

The current build is intentionally dependency-light. On this machine the engine is built with a vendored Zig toolchain, so no Visual Studio, CMake, or package manager is required. 

# from the repository root
python build.py            # build engine + sandbox
python build.py run        # build and launch the demo
python build.py test       # run math / ECS / job / script tests
python build.py --compiler mingw   # build with MinGW-w64 instead of Zig

# optional: the same build through CMake and Ninja
cmake -S . -B build/cmake -G Ninja -DCMAKE_TOOLCHAIN_FILE=cmake/zig-windows.cmake
cmake --build build/cmake

# render a real Blender scene
blender --background scene.blend --python tools/bge_export.py -- --out build/scene
build\bin\bge_sandbox.exe --scene build\scene\scene.bgescene --headless --screenshot out.png

# drive the scene from Python
build\bin\bge_sandbox.exe --script assets\scripts\demo.py
