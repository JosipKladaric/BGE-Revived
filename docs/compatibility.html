Compatibility

Familiar where it matters. Modern underneath.

Existing BGE projects should not need a full rewrite to benefit from the new runtime. We expose a versioned bge module and map the most-used 2.49b-era concepts, while documenting the places where a cleaner API is unavoidable.

Compatibility rules

Behaviour first

If a legacy call has a safe modern equivalent, the wrapper preserves its observable behaviour (units, local/world space, ordering). If not, it raises a clear error rather than silently doing something different.

No hidden globals

Global state is explicit on bge.logic. Scripts can still use the classic shims during migration; new code is encouraged to use entities and components directly.

Versioned module

bge.__version__ and a compatibility level report what is supported. Deprecations are documented and kept for at least one minor cycle.

Performance honesty

Per-frame Python property access is fine for gameplay, not for thousands of objects. Bulk APIs and native components exist for hot paths.

Status

Partially implemented. The embedded CPython host and the core bge module exist and are covered by the test suite: types, object lookup, transforms, visibility, scene spawning and per-frame handlers. Controllers, logic bricks, timers and scene switching are scheduled for M1. This page is the contract we will implement against; it is intentionally published before the code so the API surface is reviewed rather than accidental.
